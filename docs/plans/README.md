## 建议实施顺序

1. 桌面端阅读布局 P0：正文限宽与两栏层级。它直接修复大屏阅读宽度，也是三栏方案里中栏宽度的前提。
2. 桌面端阅读布局 P1：分隔条 hover 与窗口状态记忆。窗口记忆会让后续三栏尺寸调整更容易验证。
3. AI 助手 MVP：先验证桌面应用内置 Pi 核心与后台运行时，再接文章问答及会话隔离，为三栏右栏提供运行期状态；独立聊天页和跨重启历史后续再做。
4. 三栏阅读工作台：依赖第 1 项的正文宽度契约与第 3 项的会话模型；第一版只保留运行期会话。

## 桌面端列表-详情阅读布局

- 现状核对：`shared` 中没有 `ReadingContentMaxWidth`；`ArticleScreen` 正文 `Column` 仍只有 `padding(horizontal = 16.dp)`；`AdaptiveListDetail` 没有 hover 反馈；`desktopApp` 的 `Window` 未传 `state`。
- 未实现项：P0-1 正文最大宽度 720dp（`ArticleScreen`、`PinScreen`）；P0-2 详情栏底色/层级；P1 分隔条 hover；P1 窗口尺寸与位置记忆；P2 空详情栏提示（可选）。
- 明确不做：改 `RenderMarkdown`；拆分超大设置/个人页/评论页；改 840dp 触发门槛与 320/480dp 最小宽度；为 `widthIn` 新增包装函数。
- 验收：双栏 1360×860 与 1920×1080 实机截图、深色主题、窄窗口回归、拖动分隔条到两端、翻页与切换回答手势、重启后保留窗口状态。

## 内置 AI 助手

- 现状核对：`feature:ai` 只有 `CustomAi.kt` 与 `CustomAiConfigDialog.kt`；导航层没有聊天路由；数据库没有聊天表；入口只有文章「总结本文」。
- 已有底座：OpenAI 兼容总结请求、配置持久化、流式 Markdown 渲染能力；既有总结路径保留。
- 已选方向（2026-11-04）：桌面应用内置后台运行时，直接复用 Pi agent 核心与模型层，不要求用户另装 Claude/Pi CLI 或 Node。
- MVP 未实现项：进程桥接、文章问答 UI、按账号与文章隔离的运行期会话、取消与错误处理、上下文和工具回合预算。
- 关键约束：Pi 是 TypeScript 库，尚未验证本项目打包运行；移动端执行面不纳入首版；模块边界、明文密钥现状和知乎直答用途限制仍然适用。
- 后续范围：跨重启历史、独立聊天页、全局入口与任意正文选区回调；首版不新增 JSON 历史文件或聊天表。

## 三栏阅读工作台

- 现状核对：主壳只有列表/详情双栏，没有第三栏；AI 只有「总结本文」弹层。
- 未实现项：第三栏与宽度约束；两条可拖动分隔条；文章隔离的对话、草稿与滚动位置；选中文字进入提问框；三档宽度自适应（三栏 / 抽屉 / 独立对话页）。
- 关键约束：最小宽度预算 1232dp，建议 1280dp 启用；三栏尺寸与显示状态由主壳持有；第一版只保留运行期会话，不做跨重启历史；新交互只接 Compose Markdown。
- 与其他方案的关系：中栏宽度沿用桌面阅读布局的 720dp 上限；右栏复用 AI 助手的会话模型。
